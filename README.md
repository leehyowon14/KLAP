# KLAP macOS

메뉴바에 상주하는 KLAS 학습 관리 macOS 앱입니다. 앱을 열면 관리 화면이 표시되고, 실행 중 다시 열어도 화면에 접근할 수 있습니다. 메뉴바 아이콘 우클릭으로 바로 종료할 수 있습니다. 기본적으로 Dock 아이콘 없이 실행되며, 미리보기를 열면 Dock에 표시됩니다. 미리보기의 ⌘Q는 미리보기만 닫고 메뉴바 작업은 계속됩니다.

## 0.2.1.1-hotfix 베타

Apple Silicon용 macOS 13 이상 패키지입니다. ZIP을 풀고 KLAP.app을 응용 프로그램 폴더로 옮겨 실행합니다. Developer ID 서명·공증 전 베타이므로 Gatekeeper가 실행을 차단할 수 있습니다. 출처를 확인한 경우 시스템 설정 → 개인정보 보호 및 보안에서 실행을 허용할 수 있습니다.

변경 내역은 [CHANGELOG.md](CHANGELOG.md)를 참고하세요. 0.1.0 사용자는 최신 버전을 직접 설치해야 합니다. 0.2.0 이상에서는 앱 내 자동 업데이트를 사용할 수 있습니다. 다만 기존 버전에서 App Translocation으로 업데이트가 차단되면 이번 핫픽스는 직접 다운로드하여 교체해야 합니다.

## 실행

macOS 13 이상, Swift 5.9 이상과 Go가 필요합니다. 앱 아이콘 컴파일에는 Icon Composer를 지원하는 Xcode가 필요합니다.

```sh
bash scripts/build.sh
open dist/KLAP-Dev.app
```

기본 빌드는 `KLAP-Dev.app`입니다. 배포용 앱은 `bash scripts/build.sh --release`로 생성합니다.
개발 앱은 별도 bundle ID, 설정·캐시·Keychain을 사용하며 다시 로그인해야 합니다. 정식 릴리스 자동 업데이트는 비활성화됩니다. 두 앱을 동시에 실행할 수 있지만 같은 KLAS 계정으로 동시에 수강하거나 같은 캘린더에 동기화하는 것은 피해주세요.
처음 Applications 폴더 밖에서 실행하면 설치 안내와 ‘응용 프로그램으로 옮기기’ 버튼을 표시합니다. 이동 성공 후 설치된 앱을 다시 실행하며, 기존 앱 교체는 별도로 확인합니다. `/Applications`와 `~/Applications`를 지원합니다.

## 브랜치 운영

- `dev`: 기본 브랜치이자 일상 작업의 통합 기준입니다. 작은 변경을 자주 통합하는 TBD 방식으로 작업합니다.
- `main`: 검증된 릴리스 코드만 반영합니다. 배포 시 `dev`에서 `main`으로 PR을 만들고 검증 후 병합합니다.
- 작업 브랜치가 필요하면 `dev`에서 짧게 분기하고, 완료 후 `dev`로 PR을 병합합니다. 장기 기능 브랜치는 피합니다.
- 커밋은 독립적으로 리뷰·되돌리기가 가능한 최소 단위로 나눕니다.
- 릴리스 태그와 GitHub Release는 `main`의 배포 커밋을 기준으로 생성합니다.
- 긴급 수정도 `dev`에 반영하여 두 브랜치의 수정 이력이 누락되지 않도록 합니다.

빌드 시 기본적으로 `../KLAP_cli`의 `Bridge/core-ref` 커밋을 읽습니다. 다른 위치는 `KLAP_CLI_SOURCE`로 지정합니다. 원본 저장소를 수정하지 않고 `.build`에 해당 커밋을 펼칩니다. 앱에는 Go 코어와 EventKit 실행 파일이 포함되므로 실행할 때 별도 CLI 설치가 필요하지 않습니다. 현재 패키지는 빌드한 Mac의 아키텍처를 대상으로 합니다.

## 첫 실행

1. KLAS 로그인 또는 기존 CLI 계정 사용
2. 캘린더·미리 알림 권한 요청
3. 시간표, 학사일정, 미리 알림의 등록 대상 선택 또는 전용 대상 생성
4. 자동 동기화·수강 알림 설정 후 첫 동기화

권한을 거부하거나 준비되지 않았다면 ‘나중에 설정’을 사용할 수 있습니다. 동기화 대상 설정 전에는 동기화를 실행하지 않습니다. 설정에서 대상 선택을 다시 열 수 있습니다. CLI와 계정·학기·동기화 설정을 공유하며, 등록 대상을 바꾸더라도 이전 대상의 일정은 자동 삭제하지 않습니다.

## 구현

- NSStatusItem + LSUIElement로 메뉴바 상주 및 Dock 숨김
- 삼각형 없는 둥근 패널, 화면 경계 내 배치, 외부 클릭·Escape 닫기
- 스크롤 가능한 교시 단위 주간 시간표, 주말·야간·연속 수업과 겹침 배치
- 과목별 과제·공지·강의 조회 및 강의 페이지 열기
- 선택 강의, 과목 또는 전체 수강 가능 강의 자동 수강과 취소
- 메뉴바 원형 진행률과 순서 표시, 강의 완료·전환·전체 종료·실패 알림
- 서버 완료 응답 확인 후 완료 알림 전송
- 실행 중 30분 주기, 잠자기 복귀, 네트워크 복구 시 갱신
- 캘린더·미리 알림 동기화, 부분 실패 표시와 변경 충돌 선택
- 온보딩 권한 요청 및 대상 선택, 중복된 대상 이름 제외
- 온보딩은 단계별 설정만 표시하며, 완료 후 주간 시간표 표시

## 검증

```sh
swift run --build-system native KLAPCoreChecks
bash scripts/build-core.sh
bash scripts/build.sh
bash scripts/check-launch.sh
codesign --verify --deep --strict dist/KLAP-Dev.app
plutil -lint dist/KLAP-Dev.app/Contents/Info.plist
```

XCTest가 포함되지 않은 개발 환경에서도 실행되도록 Swift 검증은 실행 파일 방식으로 제공합니다. `check-launch.sh`는 계정 조회 없이 최적화 앱을 직접 실행하고 macOS 앱 열기로도 실행하여 메뉴바 생성, 아이콘, 패널 열기·닫기와 다시 열기를 검증합니다. 진행률, 시간표 범위·겹침, 빈 응답, 대상 이름 충돌을 검증합니다. Go 수강 큐 테스트는 빈 선택·중복·실패·미완료 응답·취소 후 다음 작업 방지를 검증합니다.

## 1.0 전 남은 검증

- 실제 KLAS 계정의 조회·수강·취소와 서버 상태 재조회
- 실제 EventKit 권한 허용·거부 및 대상별 동기화와 충돌 처리
- 시스템 알림과 메뉴바 진행률의 실사용 화면 검증
- 장시간 실행, 잠자기 복귀, 오프라인 전환 실기기 검증
- CLI 동시 실행과 공유 설정 변경 시 동작 검증
- 실제 로그인 항목 등록 후 재로그인 검증, 배포용 Developer ID 서명·공증, universal 패키징

현재 서명은 로컬 실행용 ad hoc 서명입니다. GUI 확인 도구가 시간 초과하여 실제 화면 조작 검증은 완료하지 못했습니다. 수정한 온보딩과 종료 버튼 배치는 SwiftUI 화면을 별도로 렌더링해 확인했으며, 패널 위치는 다중 모니터와 작은 화면 경계값으로 검증했습니다. macOS 프로세스 정보에서 실행 상태와 `UIElement` 등록은 확인했습니다.


## 신규 콘텐츠 알림과 자동 실행

- 설정에서 새 공지, 새 강의, 수강 상태 알림을 각각 제어합니다. macOS 알림 허용이 필요합니다.
- 앱 실행 중 30분마다, 잠자기 복귀·네트워크 복구·수동 새로고침 때 새 항목을 확인합니다.
- 계정·학기·과목의 최초 조회는 기준만 저장하고 기존 항목을 알리지 않습니다.
- 새 강의가 하나면 수강 시작, 여러 개면 해당 묶음의 전체 수강 시작 액션을 제공합니다.
- 알림 클릭 시 상태를 다시 조회하고, 완료·기간 만료·다른 계정의 강의는 수강하지 않습니다.
- 설정 → 자동화에서 Mac 로그인 시 자동 실행을 켜거나 끌 수 있습니다. 승인 대기 상태는 시스템 설정에서 승인합니다.
- 자동 실행 시 메뉴바에만 표시됩니다. 기본적으로 로그인 항목을 임의 등록하지 않습니다.

검사: `bash scripts/check-notifications.sh`, `bash scripts/check-login-item.sh`.
실제 신규 게시물의 시스템 배너 버튼에서 수강 완료까지, 실제 로그아웃/로그인 후 자동 실행은 별도 실기기 검증이 필요합니다.
